# Backend приложения

Выбран существующий проект Supabase `gamee`, ref `afapjvegcsurkehiljyc`, URL `https://afapjvegcsurkehiljyc.supabase.co`. В исходном задании требуется SaaS через REST или GraphQL, конкретная СУБД не названа. Реализация использует Supabase Auth, PostgreSQL RPC, PostgREST и Storage. Приложению нужен только публичный publishable/anon key. `service_role`, пароль БД и секретный API key в Android запрещены.

## Установка схемы

Скрипт [schema.sql](../backend/schema.sql) создаёт только `contest_profiles`, `contest_games`, `contest_participants`, служебную схему `contest_internal`, функции `contest_*` и Storage bucket `contest-avatars`. Найденные в существующем проекте таблицы `profiles`, `games`, `participants`, `game_moves`, `messages` не изменяются. Скрипт предназначен для SQL Editor/MCP; он не выдаётся за автоматически сгенерированную migration history.

Включите Email/Password Auth. Если email confirmation включён, после регистрации приложение сообщает о необходимости подтвердить email и не создаёт фиктивную сессию. Для тренировки можно использовать подтверждённые учебные адреса `.ru`, поскольку именно такой формат требует ТЗ. Настройка SMTP/подтверждения — настройка проекта Supabase, не обходится клиентом.

В сборку передаются `BuildConfig.SUPABASE_URL` и `BuildConfig.SUPABASE_PUBLISHABLE_KEY`. Сессия хранится шифрованным AES-GCM в Android Keystore; пароль не сохраняется. Refresh token обновляется под Mutex. Истёкшая/отозванная сессия очищается после 400/401/403 при refresh, временная сетевая ошибка её не удаляет.

## Контракт

| Требуемая операция | HTTP / ресурс |
|---|---|
| Авторизация | POST `/auth/v1/token?grant_type=password` |
| Регистрация | POST `/auth/v1/signup` |
| Изменение профиля | POST `/rest/v1/rpc/contest_update_profile` |
| Получение профиля | GET `/rest/v1/contest_profiles?id=eq.<userId>` |
| Выход | POST `/auth/v1/logout` |
| Создание игры | POST `/rest/v1/rpc/contest_create_game` |
| Список игр | GET `/rest/v1/contest_games` с пагинацией по 100 записей |
| Информация об игре | POST `/rest/v1/rpc/contest_get_game` |
| Подключение | POST `/rest/v1/rpc/contest_join_game` |
| Статистика | POST `/rest/v1/rpc/contest_statistics` |
| Результат | POST `/rest/v1/rpc/contest_save_result` |

Дополнительно: `contest_ensure_profile`, `contest_start_game`, `contest_forfeit_game`, refresh token, список популярных игроков и загрузка фотографии в Storage. Профиль создаётся при первом входе только для `auth.uid()`; глобальные триггеры чужого проекта Auth не меняются. Username — поле отображения, не средство авторизации.

## Правила сервера

Forfeit разрешён только для ACTIVE; FINISHED возвращается идемпотентно. Попытка объявить поражение в SCHEDULED отклоняется, чтобы нельзя было получить очки до разрешённого времени старта.

Создатель выбирает название, категорию, время, описание и приз 0–1000 баллов. Сервер назначает владельца, случайный seed и статус. Одно свободное место соперника захватывается атомарно под `FOR UPDATE`; третий участник не может перезаписать второго. Старт разрешён только участнику, при наличии соперника и наступлении назначенного времени. Общее `started_at` назначает сервер.

Image — классические пятнашки 3×3 с восемью фрагментами и пустой клеткой. Начальная расстановка получается 80 допустимыми ходами из решённого состояния; генератор LCG `state * 48271 mod 2147483647` реализован одинаково в SQL и `imageInitialBoard`. Одинаковый seed в записи игры даёт одинаковую картинку и расстановку обоим игрокам. Сервер повторяет последовательность перемещённых индексов 0–8, проверяет соседство с пустой клеткой и конечное состояние.

Circle требует последовательность значений `5,4,3,2,1` — от большего круга к меньшему. Это зафиксированное правило реализации. Полный игровой прототип ещё должен быть сопоставлен с этим вариантом, если макет задаёт другой жест или число элементов.

Результат определяется первым **валидным запросом завершения, полученным сервером**, под блокировкой строки. Время рассчитывает сервер; клиент не может прислать победителя, баллы или собственное elapsed. Приз начисляется один раз. Это делает результат независимым от часов устройства; влияние сетевой задержки остаётся ограничением соревновательного режима. Защита от автоматизированного решения/ботов в объём этого backend не включена.

Явный уход вызывает forfeit и поражение. Во время игры UI опрашивает `contest_get_game` раз в две секунды. При отсутствии heartbeat 45 секунд игрок проигрывает; если пропали оба, оба получают LOSS без победителя. Просрочка фиксируется при следующем запросе к игре, отдельный cron не создаётся. Проверка просрочки выполняется до обновления heartbeat, поэтому возврат после истечения времени не оживляет участника. По окончании конечного времени игры без победителя оба получают LOSS. Неактивную игру после перезапуска нельзя бесшумно восстановить как новую.

Статистика использует часовой пояс Europe/Moscow и неделю с понедельника. THIS WEEK EARNINGS — очки за завершённые победой матчи этой недели; Played Games — число побед по категориям за всё время; Scheduled Games — число созданных пользователем игр за неделю. Это уточнения там, где документ не задаёт полный контракт времени/периодов.

## Права и проверка

Все таблицы с включённым RLS. Авторизованным пользователям видны публичные профили и игры; строка результатов доступна только своему участнику. Профиль разрешает обновление исключительно собственного имени, username, местоположения и аватара. Прямые записи в игры и результаты запрещены, поля очков недоступны для клиентского UPDATE.

Публичные RPC — `SECURITY INVOKER`. Узкие операции изменения реализованы в невыставленной наружу схеме `contest_internal` как `SECURITY DEFINER` с пустым `search_path`, явной проверкой `auth.uid()` и ограниченными EXECUTE grants. Вспомогательные `initial_board` и `finish_game` не предоставлены ни `anon`, ни `authenticated`. Ни одна функция не использует редактируемые metadata пользователя для прав доступа.

Аватары публично читаются как публичные элементы профиля. Запись/замена доступна только в папке `<auth.uid()>/` bucket `contest-avatars`; разрешены JPEG/PNG до 5 МБ. Bucket не хранит приватные документы.

Контрактные тесты MockWebServer покрывают все 11 обязательных запросов, десериализацию, заголовки, logout без тела, регистрацию с email confirmation, refresh, ошибки сервера и недоступность соединения.

30.09.2026 скрипт [smoke-test.sql](../backend/smoke-test.sql) успешно выполнен в проекте `gamee` в транзакции с `ROLLBACK`. Проверены: четыре совпадения seed с клиентскими fixtures; профиль текущего пользователя и запрет некорректного имени; отказ третьему участнику; запрет чужого результата/выхода/редактирования; запрет прямого изменения баллов/победителя; отказ в старте до времени или без соперника; отклонение null и неверного порядка Circle; неверный ход Image; положительное решение Image независимым A* replay; единственный победитель и однократное начисление; поздний результат соперника; статистика; forfeit; истечение heartbeat; запрет анонимных RPC. Письма и реальные учётные записи не создавались.
