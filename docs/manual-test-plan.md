# План ручной проверки

Основание: [матрица требований](requirements.md), локальный текст задания `docs/source-task.txt`, [дизайн](design.md). Это **план**, а не отчёт об успешно выполненных проверках. Заполняйте результат только после фактического прогона на указанной сборке.

## Протокол прогона

| Поле | Значение |
| --- | --- |
| Дата / проверяющий | Заполнить |
| Git commit / versionCode | Заполнить |
| APK SHA-256 | Заполнить |
| Устройство / Android / размер экрана | Заполнить |
| Backend URL / версия миграции | Заполнить без ключей |
| Режим | Demo либо настоящий backend |
| Результат | PASS / FAIL / BLOCKED / NOT RUN |
| Доказательство | Скриншот / видео / лог / запрос |

Проверить минимум Android 14 (API 34) и используемую целевую версию, узкий экран около 360 dp и крупный экран, обычный и увеличенный шрифт. Для серверных сценариев нужны две отдельные учётные записи и два клиента. Demo-режим не подтверждает серверную синхронизацию.

## Производительность Image

Зафиксировать модель устройства, Android, тип сборки (release/profileable), дату, число повторов и размер поля. Измерить холодный запуск/переход к игре, frame timing/jank во время серии ходов, потребление памяти до/после 10 игр, время запросов начала/завершения. Сохранить исходные Android Studio Profiler/Perfetto traces и таблицу измерений. Не подставлять вымышленные значения; демонстрационный запуск не является измерением. Повторить после исправления обнаруженных регрессий.
