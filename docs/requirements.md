# Требования к Android приложению чемпионата

Матрица составлена 30.09.2026 по документу `04-Конкурсное-задание-(1).docx`, предоставленному пользователем. Документ относится к итоговому межрегиональному этапу в Мордовии **2026 года**. Требования соревнования марта 2027 года могут отличаться. Пользователь выбрал Kotlin и Jetpack Compose. В DOCX конкретная СУБД или поставщик backend не указаны: требуется SaaS с REST API и/или GraphQL. Supabase соответствует этому техническому ограничению, но его выбор не означает, что организаторы используют именно его.

Полный извлечённый текст хранится только локально в `docs/source-task.txt` и не включён в Git. Номера строк ниже относятся к этому локальному файлу, не к страницам Word. Оригинал оставлен без изменений. Текст включает абзацы, ячейки таблиц в порядке документа, сноски и внешние ссылки. Единственное встроенное изображение — логотип движения. Постраничный рендер не получен: в bundled runtime отсутствует `soffice.exe`. Для анализа требований извлечён весь OOXML-текст; номера страниц не утверждаются.

| Circle | Порядок от большего к меньшему | Число кругов, жесты и стартовое расположение — по прототипу, в тексте отсутствуют |

| Последний экран / выход из игры | Восстановление состояния и поражение при закрытии обязательны | Нужно различить уход из игры, смену конфигурации и восстановление после аварии |
| Удаление аккаунта / восстановление пароля | В тексте не названы | Не считать обязательными без соответствующих экранов Figma или уточнения пользователя |

Отдельное описание архитектуры: `https://docs.google.com/document/d/1DHGJzhbW0XN6D1P-USjFZkrPoljXKINbpMohblCme8I/edit?usp=sharing`. Прочитанная текстовая копия хранится только локально в `docs/architecture-source.txt` и не включена в Git. Основное правило — зависимости направлены во внутренние слои; бизнес-логика тестируется без UI, реального сервера и БД. MVP приводится как пример, но не является единственным разрешённым шаблоном представления.

## Конкурсный процесс

Требования этого раздела описывают действия участника на площадке. Они не являются поручением помощнику создавать аккаунты, менять чужой таск-трекер, публиковать приложение или выполнять организационные действия.

В документе требуется последовательно выполнять спринты, держать в работе не более двух карточек, переводить завершённую работу в «Готово к тестированию» с указанием коммита; статус «Завершена» выставляют эксперты (786–791). Для каждого спринта требуются отдельная ветка, сохранённый доступный проект, pull request в `main` и его закрытие (1012–1041, 1080–1082). Задание оценивают по сохранённой версии соответствующей сессии; карточки вне «Готово к тестированию» к проверке не предъявлены (1094–1095). Библиотеки/плагины должны соответствовать согласованному на площадке списку (1096).

Правила личного оборудования, наушников, устройств хранения, допуска интернета и фото/видеосъёмки (1097–1119) относятся к участию в чемпионате и не меняют функциональные требования приложения.
